# Step 5-B: 横向きタブレット一覧・閲覧専用メニュー

## 変更の範囲

スタッフ一覧のHTML/CSS/JSと模擬DOMテストを変更した。
受付・認証・読取りAPI、状態遷移、スキーマ、予測・品質管理処理、顧客用UIは変更しない。
HTTPS開発ランチャーは既存の使い捨て合成DB・legacy・訂正無効・loopback限定を維持する。
その応答にだけ `X-Omachi-Preview: synthetic` を付け、スタッフ画面に「開発専用・合成データのみ」を表示する。
通常アプリのデータや日付から合成データだと推測して表示しない。

## 一覧の構成

通常のタブレット高さでは画面全体をviewportに合わせ、ヘッダー、最新取得状況、待機・呼出・不在の組数、
切替タブを一覧スクロールの外側に置く。
未案内／最近の案内を同じ一覧領域のタブで切り替え、双方を縦に積み上げない。
各一覧のスクロール位置は画面内メモリだけで保持し、切替後も全件集計は変えない。
一覧内の説明・列見出しはstickyにし、行だけをスクロールできる。

1組1行、標準行高は最小60 CSS px。番号、時刻、人数、状態、常設「⋯」の5列とする。
番号の主部分を大きくし、年を含む受付日を同じ番号ボタン内に残す。
未案内は元のreception_order順を維持し、状態による再ソートをしない。
案内履歴は有効案内event_id降順で、案内時刻と元の受付時刻を別ラベルで表示する。
タップ領域は44 CSS px以上、三点ボタンは幅48 CSS pxを確保する。

| 条件 | 設計上の目安・確認事項 |
| --- | --- |
| 1024×768 | 約6行。上部情報と見出し以外を一覧内部でスクロール |
| 1280×800 | 約6〜7行。合成データ表示や更新中メッセージの有無で変わる |
| 768×1024（縦向き） | 約10行。列幅を縮め、1行構成と日付を維持 |
| 1440×900（PC例） | 約8行。マウス・キーボードで同じメニューを開く |

上記は60px行と余白の設計からの目安で、実ブラウザで測定した件数ではない。
ブラウザUIで使える高さ、フォント、文字拡大、エラー表示で変わるため、一画面の件数は固定しない。
高さ540px以下では一覧の最小領域を残し、必要に応じて外側の縦スクロールも許可して情報を隠さない。
幅620px以下では行を無理に潰さず横スクロールできる最小幅を設ける。主要対象は横向きタブレットである。
ログイン画面へタブレット用の高さ制限は適用しない。

## スワイプとメニュー

タッチ／ペンのPointer Eventsで、指を離した時だけ判定する。
右方向72px以上、縦の最大移動20px以内、横移動が縦移動の3倍以上、1.2秒以内を必要とする。
途中で縦方向が優勢になった操作や左への移動は、最後に横へ戻っても採用しない。
複数指、pointercancel、lostpointercapture、行からの離脱、ウィンドウのフォーカス喪失、一覧スクロールで中止する。
マウスドラッグでは開かず、常設「⋯」から開く。

`touch-action: pan-y pinch-zoom` により縦スクロールと拡大をブラウザに残し、
pointermoveをpreventDefaultして縦スクロールを奪わない。
移動後のポインター由来クリックを500ms抑止し、スワイプ末尾のクリックが番号ボタン等へ落ちることを避ける。
キーボード由来のクリックはこの抑止に含めない。
閾値と500msの抑止が実機で操作遅延や誤判定を増やさないかは手動検証する。

スワイプと「⋯」は同一の表示関数を使う。開けるメニューは1つだけで、対象番号と現在状態を明示する。
操作名はサーバーのallowed_actionsにある既知項目だけを、通常のリスト文章として表示する。
状態遷移の別実装、実行ボタン、ダミーの操作ハンドラーは追加しない。
legacyの合成プレビューなど許可項目がない場合は、利用可能な項目がないことを表示する。
「閲覧専用プレビュー・実行できない」と明記し、状態変更APIは呼び出さない。

メニューを開くとその領域へフォーカスを移す。Esc・閉じるで元の「⋯」へ戻し、
別行、外側の選択、フォーカス移動、タブ切替、スクロールでは閉じる。
初期仕様では再取得開始でも閉じたが、2026-11-04の修正で背景更新時の無条件閉鎖を廃止した（下記追記）。
静的な説明リストなのでrole=menu/menuitemを使わず、見出し付きregionと通常の閉じるボタンを用いる。
タブはtablist/tab/tabpanel、aria-selected、roving tabindex、左右キー・Home・Endに対応する。
番号は従来どおり既存のoperation-contextだけを読む。詳細を閉じる際は元の番号へフォーカスを戻す。

参考：[Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)、
[touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)、
[WAI-ARIA Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。

## 更新・認証・データ保護

5秒更新、全ページ取得、両一覧のview_version一致、受付ID重複検査、世代による古い応答破棄を維持する。
タブ切替やメニュー表示では通信経路を追加せず、認証が確認され一覧がcurrentである場合だけ表示を許可する。
2026-11-04から、検証済み一覧がある通常の背景更新ではメニュー・スワイプ・タブを維持する。
対象行・revision・DB識別子・世代・モード等が変わったときと、検証失敗時には閉じる。
失敗・409・ログアウト・期限切れ・非表示化で、受付情報に加えてメニューの対象番号・状態・説明も消す。
古いDOMノードを保持して呼び出しても、現在の行に対応しないメニューは開かない。
HTML文字列としてAPI値を挿入せず、textContentで描画する。

認証Cookie、CSRF、認証主体、期限、TLS、Host/Origin制限は従来のまま。
受付順、受付時刻、スナップショット、保存済み予測、実待ち時間、訂正・品質問題を変更する処理はない。
開発用ラッパーの業務POST拒否も維持する。LINE関連の要素・APIは追加しない。

## 実機確認の手順と残る工程

この実行環境にはChrome/Chromium/Firefox/Playwright/Seleniumがなく、今回の描画・実タッチは未検証である。
前工程で利用者が確認したWindowsブラウザの基本動作を、今回の新レイアウトやジェスチャーの確認済み扱いにはしない。
既存の[HTTPS手順](staff-readonly-ui-https.md)で合成プレビューを起動し、以下を確認する。

1. Windowsの専用HTTPSオリジンでログインし、「開発専用・合成データのみ」を確認する。
2. 開発者ツールのviewportを1024×768、1280×800、768×1024、PCサイズに変え、100%/125%の文字拡大でも番号・日付・人数・状態・三点が欠けないことを確認する。
3. 通常ウィンドウでもブラウザUIがある状態で上部組数が残り、一覧だけがスクロールすることを確認し、実測の表示行数を記録する。
4. 実タブレットで縦・斜め・短い移動、複数指、長押し中断、右スワイプを試し、縦スクロールを妨げず、指を離す前に開かないことを確認する。
5. 「⋯」、Tab/Enter/Space、左右キー/Home/End、Escで表示とフォーカスを確認する。操作項目が実行ボタンに見えないことも確認する。
6. 同じ対象の背景更新ではメニューを維持し、対象変更、タブ切替、別行選択、通信断、期限切れ、ログアウトでは消えることを確認する。
7. 開発者ツールのNetworkで、ログイン/ログアウト以外はGETのみであり、operations/seating-corrections等のPOSTがないことを確認する。認証情報・Cookieが見える画像を共有しない。

多数行・ページングと組数は合成DOM試験で151件以上を扱う。
現行ランチャーの少数の合成行だけでは、実機での大量行スクロールは確認できない。
実DBを代わりに接続せず、必要なら後続の明示的な合成フィクスチャ拡張で確認する。

状態変更を接続する次工程では、最新情報の再取得と人の確認、操作IDの作成・保持・再送照会、
期待revision/write_epoch、409時の自動再実行禁止、訂正対象の有効イベントIDと理由を設計・結合テストする。
今回の静的な説明項目をそのまま実行ボタンに変えない。

## 2026-11-04: 背景更新の画面揺れ・操作中断の修正

利用者のWindowsブラウザ確認で、基本レイアウトは維持したい一方、5秒ごとの上下移動と操作中断が報告された。
原因は次の実装にある。

- 更新開始時に通常フローへメッセージを表示し、完了時に隠すため、一覧に使える高さが変わる。
- refreshから呼ぶabortReadsが無条件にメニュー・スワイプを消し、タブも無効化する。
- 同一データでは行を再生成しないが、1行変わると一覧全体をreplaceChildrenで作り直す。
- 初期化は毎回ではなく失敗・再認証等で行っていた。非同期世代検査・ページングは揺れを直すために撤去しない。

[ADR-0014](../adr/ADR-0014.md)で初期の更新開始時閉鎖だけを見直した。
セッションと全ページを背景取得し、両一覧の版・DBメタデータ・順番・重複・上限の確認後に同期反映する。
受付IDと一覧種別で行を再利用し、表示項目・revision・許可操作・有効イベントが変わる行だけを置換する。
追加・削除は必要な行だけに限定し、未変更行のフォーカスやDOMを維持する。
スクロールは取得開始時点へ戻さず、反映直前の位置を保持する。

対象とDB保護情報が不変なら、無関係な受付で全体版が進んでもメニュー・詳細を閉じない。
進行中のスワイプも同じ対象なら維持する。対象や世代・設定が変われば閉じる。
通信失敗・409・不正形式・認証失敗時には以前どおり情報を消し、古い情報を最新と表示しない。
閲覧詳細の最初の取得は一覧の版と照合し、後続更新では対象単位で継続可否を確認する。

更新表示と最終確認時刻は共通44pxの枠に置き、通常更新ではローディング表示・薄色化・タブ無効化を行わない。
時刻の数字は等幅とし、既存のscrollbar-gutterを維持する。失敗で受付情報が消えても上部の枠は残す。
正常な最終確認時刻の更新は残るが、行・集計・操作対象を動かす理由にはしない。
この固定枠によって初回工程の表示行数の目安は変わり得るため、件数は実測で確認する。

旧「再取得開始で失効」テストは新方針へ更新した。
25回の同一ポーリング、対象不変の他受付追加・変更、対象/世代/設定の変更、
151件超のページ取得途中の表示保持、一括集計、通信途中のスクロール・スワイプ、
フォーカスとDOM同一性、失敗時の非表示、メニューの業務POST不在を合成データで検証する。
CSS/DOM試験は高さを変える入力を抑えた確認であり、実際の描画やタッチ感度の証明ではない。

修正後はWindowsブラウザで、25回以上の更新をまたぐ同一行・メニュー・詳細・スクロール位置を確認する。
1024×768・1280×800・縦向き・PCと文字拡大で、上部情報と44px枠、実測行数、エラーの読取りを確認する。
実タブレットでは更新をまたぐスワイプ、縦スクロール、画面外への移動・複数指による中断を再確認する。
修正後の実画面・実タッチ再検証は未実施。既存プレビューの少数行だけで大量行の実機性能を確認済みとはしない。

将来の更新API接続では、保持したメニューを信頼して直接更新せず、実行直前の対象再取得・確認画面・
操作ID保持・結果照会・expected_revision・write_epochと409の自動再実行禁止を必須にする。
今回、状態変更API・LINE・実DB設定・モデル・品質承認を変更しない。
