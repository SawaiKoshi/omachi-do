## 既存ADRとの関係と整合性の注意点

- 0001〜0004の特徴量・既存Excel前処理・RF・評価方針は変更しない。
  SQLiteの正確な小数分・日付またぎ実績を、Excelの同日・整数分ラベルへ自動変換しない。
- 0006は0005のDB章を拡張する。v1互換性と自動移行禁止を維持する。
  0007は受付登録の冪等キーを置換せず、別のスタッフ操作台帳を追加する。
- 0008は0005の「案内済みから変更しない」に対し、監査付き訂正専用APIの例外を追加する。
  通常APIの終端制約と、キャンセル済みから戻せない制約は維持する。
- 0009〜0012は0005で将来課題だった品質抽出・ブラウザ認証・読取り・開発HTTPSの実装範囲を補う。
  実運用の品質承認、店舗LAN、本番移行・復旧の完成を意味しない。
- 移行、ストア統合、操作保護、訂正、認証基盤の各設計書は工程別の記録であり、
  後続工程で実装された機能を「未実装」と記す箇所が残る。現在の範囲は上表の後続資料・ADRとコードで確認する。
  [HTTPS手順](../design/staff-readonly-ui-https.md)末尾の全件試験未完了は診断修正時点の記録。
  後続の[タブレット工程](../design/staff-tablet-ui.md)ではPython 1,613件・JavaScript 208件成功を記録している。
- 閲覧専用UIのWindows基本動作は利用者から確認済みと報告された。
  新レイアウトの描画・表示行数・実タッチ・拡大表示は未検証で、0013の手動確認を残す。
  過去のブラウザ確認を新レイアウトの検証結果として扱わない。
- [個別スマートフォン設計](../design/personal-reception-view.md)のAPI、QR、LINE、動的残り時間モデルは将来提案。
  今回のADRで実装済み・承認済みに変更しない。
