# ADR-0018: AIチーム（agent-team）による計画・実装・レビューの分担

- 状態: 提案（このPRのマージで採用）
- 記録日: 2026-11-25

## 背景

複数のプロジェクトを並行して進めるため、ユーザーの作業をプランの承認・レビュー指摘の取捨・マージの判断に絞り、計画・実装・レビューをAIのチームに任せたい。T3 Code v0.1.0（Orchestrator V2）では、エージェントがT3 Code MCPを通じてスレッドを作成・起動・待機し、`delegate_task` で別のプロバイダー（Codexなど）の子スレッドを起動できる。

## 決定

1. 統括（Claude）が `agent:ready` のIssueを拾い、タスクごとにworktreeとブランチ `agent/<Issue番号>-<名前>` を作る。プランと実装は同じClaudeの子スレッドでモデルを切り替えて行い、レビューは別モデルのCodexが読むだけで行う。
2. ユーザーの判断はプラン承認・指摘の取捨・マージの3か所。統括はユーザーの答えを原文のまま子に渡す。
3. 検証は `.agents/team/gate.sh` に集約し、PRの前と修正のたびに通す。同じ失敗が2回続いたら止まってユーザーに回す。
4. Claude Codeの安全ガード（PreToolUseフック）は、破壊的な操作・秘密情報の読み出し・依存の追加・安全設定自体の変更を止めるだけにする。自動で実行・修正・承認しない。迂回用の設定は作らない。Codexはread-onlyのサンドボックスで守る。
5. スキル本体はCodexと共通の `.agents/skills/` に置き、Claude Code用には `.claude/skills/` に本体を読むよう案内する入口だけを置く。

## 比較した案

- Claudeがプラン、Codexが実装、Claudeがレビュー：既存の作業の分担（Claude実装・Codexレビュー）と合わないため不採用。
- 同じタスクを両方に実装させて比較：手間とトークンが約2倍になるため不採用。
- タスクの入口をNotionにする：接続とデータベースの準備が要るため、まずはGitHub Issuesにする。

## 未確認

- T3 Code MCPのツール名と接続方法（スキルは一覧に表示されたツールを使うよう書いている）。
- 実際のタスクでの所要時間・トークン量。
