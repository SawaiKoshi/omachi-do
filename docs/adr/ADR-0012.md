# ADR-0012: 合成データ専用HTTPSプレビューの隔離

- 状態: 採用済み方針の後追い記録（今回レビュー対象）
- 記録日: 2026-11-02
- 記録区分: Step 5-BのHTTPSプレビュー・診断修正・合成表示で採用した判断を今回初めてADR化する
- 関係: [ADR-0006](ADR-0006.md)の合成移行と[ADR-0010](ADR-0010.md)の認証を開発検証する限定環境

## 背景

Windowsブラウザ／WSL2でSecure Cookieを確認するにはHTTPSが必要だが、実DB・モデルや店舗ネットワークを
使う必要はない。HTTPS不備を回避するために認証条件を緩めることも避ける。
起動エラーを一つの汎用文へ置き換えるだけでは、安全な原因切り分けが難しい。

## 決定

1. `staff_https_lab.py`を明示実行する開発専用環境とする。
   新しい一時領域へ合成v1を生成し、その合成DBだけをv2へ移行する。
   アプリの自動移行ではなく、実DB・既存実験DB・モデル・待受ホストを指定する引数は提供しない。
2. `127.0.0.1`固定、既定8443、単一worker、reloadなし、proxyヘッダー信頼なし、アクセスログなしで起動する。
   HTTPリスナー・HTTPフォールバック・LAN公開は追加しない。
   `legacy`・訂正無効を維持し、業務時刻は合成fixtureに固定、セッション期限は実時間で計測する。
3. ラッパーで`/staff/`のGET/HEADとセッションPOST/DELETEだけを許可する。
   受付・案内・訂正・品質管理の書込みを拒否し、顧客用APIも通さない。
   モデルには一時領域の不存在パスを明示し、既存モデルや環境変数の実DB設定を使わない。
4. TLS証明書・葉の秘密鍵は利用者がリポジトリ外に用意する。
   所有者・通常ファイル・単一リンク・秘密鍵の所有者限定権限と証明書/鍵ペアの読込みを検査する。
   鍵をGitへ含めず、信頼ストア・hosts・ファイアウォールを自動変更しない。
   サーバーでのペア読込み成功だけでWindows側の信頼・名前解決の確認済みとはしない。
5. 開発専用共有資格情報は32文字以上の印字可能ASCII、空白のみ不可とし、TTYの非表示入力か
   専用開発環境変数から受け取る。起動引数・ログ・エラーへ値を出さない。
   `--check`と固定診断コードでTLS、資格情報、loopbackポート、合成DB準備の失敗を分ける。
   任意例外文・秘密・内部パスを表示せず、ポート自動変更や既存サービス停止もしない。
6. ラボ応答だけに`X-Omachi-Preview: synthetic`を付け、UIはその印から合成データであることを明示する。
   日付や内容からの推測には使わず、この表示を認証や書込み許可の根拠にしない。
   通常終了時に一時領域を破棄する。

## 理由

本体の認証を弱めずに実TLS・Cookie・読取りを試し、誤操作や設定ミスが実データへ到達する経路を減らせる。
失敗分類を固定コードにすれば、秘密や例外全文の共有なしで診断できる。

## 代替案

| 案 | 判断 |
| --- | --- |
| 実開発DBや既存実験DBを表示 | 検証に不要な実データへの接続を生むため不採用 |
| HTTPへ戻す、証明書検証を無効化 | Cookie・HTTPSの検証目的を満たさないため不採用 |
| 0.0.0.0で待受、信頼設定を自動変更 | loopbackの開発範囲を超えるため不採用 |
| 例外全文を起動エラーへ表示 | 秘密・パス等の漏洩を避けるため固定コードを採用 |

## トレードオフ・影響

証明書信頼、Windows側名前解決、WSL転送は手動準備が必要。事前ポート検査後の競合も残る。
少数の固定合成行は実運用負荷や大量行の実機スクロールを検証しない。
強制終了時の一時ファイル清掃を常に保証する構成でもない。
店舗LAN・実DB・状態変更プレビューとして流用せず、必要時は別設計とする。

## 検証方法・実装範囲

[staff_https_lab.py](../../staff_https_lab.py)、[ラボ試験](../../tests/test_staff_https_lab.py)を照合した。
一時証明書によるホスト名検証付きTLS、Cookie属性、Origin/CSRF、失効、業務POST拒否、
DB不変・削除、権限・リンク、診断の秘密非表示、ポート競合・再起動を検証する。
自動試験はOSやブラウザの信頼ストアを変更しない。
[HTTPS手順](../design/staff-readonly-ui-https.md)の元起動失敗は入力条件未確認で、特定原因を断定していない。
後に利用者はWindows基本動作を確認したが、全TLS攻撃条件や新タブレット操作の確認完了とはしない。
現UIの合成表示と検証範囲は[タブレット記録](../design/staff-tablet-ui.md)も参照する。
