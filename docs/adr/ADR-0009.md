# ADR-0009: SQLite学習候補の原則禁止と品質承認境界

- 状態: 採用済み方針の後追い記録（今回レビュー対象）
- 記録日: 2026-11-02
- 記録区分: Step 5-Bの品質レビュー・抽出工程で採用した判断を今回初めてADR化する
- 関係: [ADR-0002](ADR-0002.md)のExcel監査とは別のSQLite境界。[ADR-0003](ADR-0003.md)・[0004](ADR-0004.md)は維持

## 背景

訂正で実待ちが正しくなっても、元のスナップショットや周辺受付の品質問題は残る。
既存`prepare_training_data()`は候補を再判定するため、品質フラグ付き全行を渡すだけでは不許可行が復活し得る。
また共有スタッフ認証では、誰が資料を確認して学習利用を認めたかを本人確認できない。

## 決定

1. 学習利用は既定で禁止する。品質問題のレビューは`hold / exclude / clear`、
   受付単位の判定（assessment）は`hold / exclude / eligible`とし、両者を区別する。
   既存問題・過去判断を更新・削除せず、理由、根拠、日時、主体、対象を追記する。
2. 共有ヘッダートークンのHTTP経路にはhold/excludeだけを認める。
   ブラウザセッションの品質POSTはすべて拒否する。
   品質参照の`training_use=blocked`は維持し、clear/eligibleを有効にするHTTP設定・環境変数を設けない。
3. clear/eligibleのライブラリ経路は、サーバー側から明示的に渡した信頼済み承認機構を必須とする。
   本人確認済み`staff_account`、権限、資料参照と確認根拠、対象revision・案内イベント・確認範囲を
   承認機構が独立に検証する。要求本文の確認チェックだけでは承認しない。
   実運用の承認機構は未接続で、成功経路は合成テストの承認機構でのみ検証している。
4. 品質操作もoperation_id・revision・write_epochを検査する。
   品質操作自身は受付revisionを増やさないため、全体event/issue/review最大ID、
   問題の期待レビュー番号・受付の期待assessment IDも比較し、古い判断や同時操作を拒否する。
   判断と操作台帳は同一トランザクションで保存する。
5. 独立した`extract_candidates()`で、DataFrameや前処理を作る**前**に強制除外する。
   `mode=ro`・query_onlyでBEGIN後の最初のSELECTから一貫したSQLiteスナップショットを固定する。
   次の全条件を満たす行だけを候補として返す。

   - 既知のv2、訂正・品質問題の網羅性とレビュー・台帳の整合性を検証できる。
   - 最新assessmentがeligibleで、現在revision・有効案内イベント・世代と一致する。
   - 全問題の最新レビューがclearで、現在実績と必要な検査範囲に対応する。
   - assessmentの全体event/issue/review境界が現在値と一致し、承認の根拠・権限が現在も有効である。
   - 既知の品質判定版・データ契約であり、受付日時・有効案内日時・有限非負の実待ちが整合する。

6. 未評価・未解決・古い判断・無効化案内は除外する。未知形式や品質問題の欠落、履歴不整合では
   一部候補を返さず抽出全体を停止する。再案内で自動解除しない。
   除外行はIDと理由だけを返し、学習用の人数・日時・ラベルを下流へ渡さない。
7. 契約`rf-intake-actual-wait-v1`と判定版`sqlite-quality-v1`を固定する。
   候補とbatchには受付ID・revision、有効案内event_id、assessment ID、DB識別子・世代、
   検査境界、契約・判定版、抽出時刻を追跡可能に残す。
   保存予測・スナップショットを特徴量に含める許可ではなく、clearでも元の値を修復したとは扱わない。

## 理由

不許可行を抽出境界で取り除けば、後段の既存候補判定が未承認ラベルを再採用する経路を防げる。
問題単位の解決と受付単位の候補化を分け、部分解決や新しい訂正による古い許可の使い回しを避ける。

## 代替案

| 案 | 判断 |
| --- | --- |
| 品質フラグ付き全行を既存前処理へ渡す | 再判定による混入を防げないため不採用 |
| 案内実績があれば採用、共有トークンで解除 | 未評価・他問題・本人確認・根拠の不足を見落とすため不採用 |
| 行ごとの状態だけ確認して抽出 | 並行訂正や他受付由来の新問題を取りこぼし得るため不採用 |

## トレードオフ・影響

全体境界を使うため無関係な受付・レビューでも旧判定が失効し、検査・再確認の負荷が大きい。
抽出結果は一時点の候補であり、将来の学習開始前にも鮮度・権限を再検証する必要がある。
実運用の承認機構、実データ抽出・出力、学習との接続は未実施。
小数分・日付またぎを既存Excelの同日・整数分ラベルに自動変換するアダプターも未実装である。
候補化は再学習やモデル採用の許可ではなく、現行RF・前処理・評価結果を変更しない。
