# ADR-0008: 案内訂正と影響受付の原子的な品質保留

- 状態: 採用済み方針の後追い記録（今回レビュー対象）
- 記録日: 2026-11-02
- 記録区分: Step 5-Bの訂正API工程で採用した判断を今回初めてADR化する
- 関係: [ADR-0005](ADR-0005.md)の案内済み終端制約に訂正専用の例外を追加。[ADR-0007](ADR-0007.md)を再利用

## 背景

誤案内後に再受付させると元の受付順と実待ちの基点を失う。
状態だけを戻すと誤った実績や、誤案内中に受付した他の組の不正確なスナップショットを見落とす。

## 決定

1. 認証付き`POST /staff/receptions/{id}/seating-corrections`だけで訂正する。
   新規訂正はv2、`revision_required`、`seat_corrections_enabled=1`の全条件を必要とする。
   operation_id、expected_revision、write_epoch、有効な対象案内event_id、理由コード・詳細を必須にする。
2. 現在seatedかつ対象がその受付の最新・未訂正の案内イベントであることを検査する。
   復帰先はサーバーが対象イベントのfrom_statusからwaiting/called/absentに決め、利用者に指定させない。
   元のID・番号・受付日時・順番・人数とcalled_atを保持し、現在のseated_at・actual_wait_minutesをNULLへ戻す。
3. 元イベントを更新・削除せず、参照・理由・前後状態を持つ`seating_corrected`を追記してrevisionを増やす。
   再案内では元の受付日時から実待ちを再計算する。受付時スナップショット、予測JSON、初回応答は不変とする。
4. 誤案内event_idと訂正event_idの開区間を全体イベント順で走査する。
   同一時刻でもevent_idで区別し、次の問題を原因訂正と証拠に結び付けて追記する。

   | 対象 | 問題 |
   | --- | --- |
   | 訂正対象 | `invalidated_seating` |
   | 区間中に新規受付した他の組 | `snapshot_context` |
   | 上記のうち受付直前の記録上の未案内組数が0 | `prediction_gate` |
   | 区間中に状態変更された他の組 | `workflow_impact`（間接影響の可能性） |

5. 状態、revision、訂正監査、全品質問題、操作結果を単一トランザクションで確定する。
   訂正前後の履歴と必要な問題の網羅性を検査し、例外だけでなく問題記録の無言の欠落でも全体を戻す。
   重なる訂正は原因ごとに別問題を保持し、再案内だけで品質保留を解除しない。
6. 通常状態変更APIでは案内済み・キャンセル済みの終端制約を維持する。
   誤取消の救済や任意の過去状態への復帰は追加しない。
   古い案内Aの再送は保存結果を返すだけで、訂正B後の状態を再び案内済みにしない。

## 理由

取り消す対象をイベント単位で固定すれば、再案内後の古い訂正を拒否できる。
訂正と影響記録を一緒に確定し、不完全な品質隔離を成功として扱わない。
元の予測や集計を後から修正せず、当時の入力と後日の訂正を区別して追跡する。

## 代替案

| 案 | 判断 |
| --- | --- |
| 通常の状態更新でseated→waitingを許可 | 元状態・対象イベント・理由・周辺影響の保証がないため不採用 |
| 旧案内イベント削除、再受付 | 証跡・元の順番・実待ちの基点が失われるため不採用 |
| 訂正対象だけ保留、時刻だけで影響抽出 | 他受付や同時刻イベントを取りこぼすため不採用 |

## トレードオフ・影響

全履歴走査は書込ロック時間を延ばす。workflow_impactは因果関係を断定せず保守的に保留する。
記録されない現場判断や匿名の予測表示への全影響は追跡できず、既に表示した数値も撤回できない。
待ち組数は現行RFの特徴量ではないため補正式を追加せず、0組での既存予測抑止だけを区別する。
実DBの訂正有効化、状態変更UI・重要操作の確認画面は未実施。
品質問題の記録だけでは学習混入防止は完了しないため、[ADR-0009](ADR-0009.md)の抽出境界を必要とする。
