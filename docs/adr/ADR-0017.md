# ADR-0017: call・absent限定合成ラボと操作横断の復旧境界

- 状態: 採用（8445の合成APIラボを実装。2操作のブラウザ接続・共通ジャーナル・排他は未実装）
- 記録日: 2026-11-11
- 関係: [ADR-0015](ADR-0015.md)・[ADR-0016](ADR-0016.md)を、新しい合成入口に限定して拡張する。
  8443の[ADR-0012](ADR-0012.md)、8444のcall限定入口・UIは置換しない。
  業務規則は[ADR-0005](ADR-0005.md)、操作保護は[ADR-0007](ADR-0007.md)、
  認証は[ADR-0010](ADR-0010.md)、品質境界は[ADR-0009](ADR-0009.md)を維持する。

## 背景

呼出後の不在をブラウザへ接続する前に、既存operationsの遷移・再送・拒否・認証を合成DBで検証する必要がある。
既存8444の許可範囲を広げると、call限定として確認済みの入口とUIの意味が変わる。
またcall用・absent用に独立した未確定記録を作ると、結果不明のまま別操作を開始できてしまう。

## 決定

1. 8443は閲覧専用、8444はcall限定のまま維持し、別入口`staff_call_absent_https_lab.py`を追加する。
   CLIの待受は`https://staff.localhost:8445`・127.0.0.1・単一workerに固定する。
   DB・モデル・ホスト・ポート・worker・許可action・汎用書込みを指定する引数を作らない。
   自動試験のfactoryだけは衝突しない一時TLSポートを指定できるが、任意DBは受け取らない。
2. 新規のPython一時領域に合成v1を生成し、そのDBだけを明示的にv2へ移行する。
   `staff_write_mode='revision_required'`、`seat_corrections_enabled=0`とする。
   実DB・既存実験DB・バックアップへ接続せず、モデルには一時領域の不存在パスを指定する。
3. ラッパーが通す業務POSTは既存`/staff/receptions/{id}/operations`のcall・absentだけとする。
   JSONの型・項目・重複キー・非有限数・サイズ・受信期限・Content-Type等を厳密に検査する。
   return・seat・cancel・訂正・品質操作・旧更新API・顧客用APIを拒否する。
   Cookie・Origin・CSRF・操作ID・revision・write_epoch・原子的な保存は既存アプリとストアに任せる。
   認証や状態遷移を別実装しない。既存入口を汎用化せず、新入口に固定の小さな通信ゲートを置く。
4. 不在への新規状態変更はcalled→absentだけとする。waiting・seated・cancelledからは拒否する。
   最新の保護情報によるabsent→absentは既存仕様のno_changeであり、新たな不在イベントを作らない。
   元のID・番号・受付日時・受付順・人数・保存済み予測・スナップショットを変更しない。
   called_atを維持し、不在時刻はイベントに記録する。元イベントは削除・更新しない。
   復帰は既存のabsent→waitingであり、今回のラボでは許可しない。
5. 状態変更の時刻規則と、実案内日時から元の受付日時を引く実待ち時間の計算規則を変えない。
   不在時間を差し引かず、案内前に実待ち時間を確定しない。不在も未案内総数へ含める。
   品質問題・レビュー・承認を変更／自動解除しない。新イベントで古い品質確認が失効する既存の抽出保護を維持する。
6. 新入口は`X-Omachi-Preview: synthetic`と`X-Omachi-Preview-Actions: call,absent`を返す。
   既存call UIはcall完全一致を要求するため、8445では書込みUIもジャーナルも有効化しない。
   汎用allowed_actionsやwrite_enabledはラボの権限表ではない。UIの表示やヘッダーだけで権限を判定せず、
   サーバーで固定の許可集合を強制する。今回の8445画面は閲覧専用とする。
7. 将来の8445 UIでは、call・absentを横断して未確定操作を一件に制限する。
   一つの共通ジャーナル、一つの同一origin用Web Lock、共通の結果照会・固定再送を使用する。
   共通ロックには既存名`omachi.synthetic.staff.call.v1`を継承し、旧callタブと別名のロックを取得して
   同時送信可能にしない。旧名のcallという文字列を操作権限の根拠にはしない。
   状態別の操作可否・確認文言・成功応答の検証は操作別に固定する。call専用検証を無条件に緩めない。
   Web Locks非対応・排他不能・保存不能・破損・環境不一致では新規送信と再送を停止する。
   これは次工程の設計であり、今回サーバー側に全端末共通の未確定操作ロックを追加したものではない。
8. 旧呼出ジャーナルの互換方針は次節のとおりとする。未確定操作を無視して新しい空スロットを作らない。
9. 保存済み結果は過去の操作結果であり、現在の受付状態とは区別する。
   同一ID・同一主体・同一本文の再送は保存結果を返すだけとし、後続操作を巻き戻さない。
   応答喪失・タイムアウト・照会404を失敗と断定せず、新IDや最新revisionで自動再実行しない。
   次工程でも確認時・確定直前のcontext取得、5秒更新との通信分離、確定成功だけの通知消去を維持する。

## 次工程の旧ジャーナル互換と復旧方針（今回未実装）

- 8444の`omachi.staff.call.pending.v1`と`omachi.staff.call.guard.v1`、形式版1はそのまま維持する。
  新しい2操作形式は版2として区別し、旧ファイルや旧呼出UIを暗黙に書き換えない。
- 8445 UIを有効化する前に、同一origin内の旧pending・guard・手動確認マーカーを検査する。
  旧記録があれば新規call・absentを止め、旧callのまま認証付き結果照会と現在状態確認を行う。
  旧版を解決できる互換読取り経路とその試験が揃うまで、UI書込みを有効化しない。
- 未確定レコードを自動変換・削除して空にしない。action・操作ID・受付ID・DB・世代・revision・作成時刻を付け替えない。
  旧／新の未確定記録が共存、guardのみ残存、不明な版、形式破損なら停止し手動確認とする。
  確定結果と現在contextを照合して旧記録を解決した後に限り、新形式の空状態を初期化する。
- 保存項目は形式版、操作ID、受付ID、database_id、固定4項目の要求、作成時刻・期限等に限定する。
  共有認証情報・Cookie・CSRF・受付詳細・予測・スナップショットを保存しない。
  24時間の通常復旧期間、期限超過／時計逆行後の最小手動確認マーカー、送信前の保存・読戻し検証を継承する。
  期限超過・ログアウト・通知消去で操作を解決済みにしない。
  版2の期限後マーカーには形式版・状態・操作ID・受付ID・database_id・action・理由を残し、
  固定本文や世代は保持しない。旧版1のマーカーはcall専用と判別し、別actionへ読み替えない。
- Cookieは同じホストのポート間で共有されるが、sessionStorageとWeb Locksはorigin別である。
  8445から8444の記録を自動検出・読取り・排他できるとは扱わない。
  ラボは一つずつ使い、旧ラボで未確定操作を解決してから停止・切替する。
  旧DB消滅・タブ閉鎖・ストレージ消去では完全復旧を保証できない。操作台帳との手動照合が必要である。

## 理由

既存operationsを通せば、不在の時刻や実績の規則を二重管理せずに検証できる。
入口を分けることで8443・8444の回帰範囲を限定し、ブラウザ側の復旧機構が揃う前に書込みを開放しない。
二つの操作に一つの未確定記録を用いることで、callの結果不明中にabsentを始める等の矛盾を防ぐ。

## 代替案

| 案 | 判断 |
| --- | --- |
| 8444をcall・absentへ拡張 | 既存入口とcall UIの確認済み境界を変えるため不採用 |
| absent専用の別ラボ | 最小権限だが、同じDBでcall→absentの結合確認ができないため今回は2操作に限定 |
| 汎用allow-writes／action引数 | return・seat等への拡張経路を作るため不採用 |
| 認証・不在処理を新しく実装 | 既存ストアと監査・計算規則が分岐するため不採用 |
| call・absentごとに別ジャーナル／別ロック | 未確定操作が二つ成立するため不採用 |
| 旧記録を無視／期限で失敗扱い | 成功済み操作の再実行や復旧情報喪失を招くため不採用 |

## トレードオフ・影響

ゲートを小さく複製するためAPI契約変更時に両ラボの試験が必要となる。今回既存ファイルの共通化は行わない。
実店舗の個人認証、複数worker、別端末間の完全な排他、記録喪失後の復旧は未完成である。
共有認証は個人の本人確認ではない。声掛けの到達・LINE通知も証明しない。
業務時計は合成fixtureの最終時刻に固定し、セッション期限は実時間で管理する。
一時領域は同じOS利用者の悪意あるコードを隔離するサンドボックスではなく、強制終了時には残存し得る。
不在時間を含む実待ち時間の学習適格性は別の品質審査事項で、自動承認しない。
RF・Excel・特徴量・推論・顧客UI・品質承認境界・実DBのモードは変更しない。
