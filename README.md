# おまちどう — データ品質監査

`step1_audit.py`はファイル選択・Excel読込・表示、`data_validation.py`は判定と集計、
`time_utils.py`は時刻変換を担当する。機械学習モデルやAPIからは、ファイルI/Oなしで
`audit_dataframe(data)`を利用できる。

## テスト

既存の仮想環境を使う。

```sh
.venv/bin/python -m pytest -q -W error
```

テストは合成DataFrameと`tmp_path`内で生成したExcelだけを使用する。
元Excelの内容を読み込まず、pandasの実ファイル読込にも一時領域限定のガードを設けている。
人数検証、取消の分類、学習候補、旧判定式との比較、時刻逆転、閉店時刻、丸め、
入力の不変性、ファイル選択、必須列・0件チェック、CLIを検証する。

確認環境はPython 3.14.4、pandas 3.0.6、NumPy 2.5.4、openpyxl 3.1.5、pytest 9.1.1。
今回の作業で依存パッケージを追加・更新していない。

## 監査コマンド

次は実データ読込を伴うため、今回の作業では実行していない。

```sh
.venv/bin/python step1_audit.py "対象ファイル.xlsx"
```

引数を省略するとカレントディレクトリの`.xlsx`を探索する。
`~$`で始まるロックファイルとディレクトリを除き、1ファイルだけの場合に自動選択する。
0件・複数件・不正なパス・必須列不足・データ0件はエラー終了する。
読込設定は従来どおり`Sheet1`、`header=1`、`B:U`、`na_values=["Null"]`。

監査結果は標準出力に表示する。元Excelへの書込、行の修正・削除は行わない。

## 判定の使い方

```python
from data_validation import audit_dataframe, summarize_audit

# dataは呼び出し側が用意したDataFrame
audited = audit_dataframe(data)
summary = summarize_audit(audited)
candidates = audited.loc[audited["学習候補"]]
```

元の行・インデックスを維持したコピーに、項目別の状態、比較可能性、不一致、取消、
重複、学習候補の列を付ける。`valid`、`missing`、`conversion_error`、`invalid_type`、
`non_finite`、`non_integer`、`out_of_range`、`total_mismatch`、`wait_mismatch`、
`time_reversed`、`cancelled`を区別する。
学習候補は取消以外で、人数・待ち時間が両方`valid`の行。
除外理由は重複し得るため、その件数の合計は学習候補外件数とは限らない。

時刻は同日として計算し、23:00を超える受付・案内を範囲違反とする。
案内が受付より前なら、丸める前に時刻逆転として検出する。
待ち時間の比較には従来の整数分への丸めを使う。日付またぎの補正は行わない。

## 互換性の確認範囲と残課題

提示された実データの基準値（全233件、暫定学習候補226件、候補外7件、人数不一致1件、
待ち時間不一致4件、取消2件、新旧人数判定差0件）は、今回再計算していない。
件数を判定ロジックに埋め込んでいない。

合成データでは、通常の入力における旧判定式との一致をテストしている。
23:00超と丸め前の短い時刻逆転を除外する仕様追加は、実データに該当行があれば件数に影響する。
実データを読める別の作業で基準件数との差分確認が必要となる。
重複の学習利用、日付・呼び出し番号の値の検証、開店時刻、人数・待ち時間の上限は、
現行の条件を維持し、追加の業務要件が決まるまで変更しない。
API実装時には、この状態コードと結果列の契約を確定する。

設計判断・代替案・意図的な仕様差分は[ADR-0002の草案](docs/adr/ADR-0002.md)を参照。
