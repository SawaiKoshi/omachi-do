# 子スレッドへの依頼文

`<...>` を埋めて送る。手動モードではユーザーにこの文を渡し、T3 Code の新しい worktree スレッドに貼ってもらう。

## プラン依頼（手順3、Claude・プラン用モデル）

```
team-plan スキルに従って、Issue #<N> のプランだけを書いてください。コードやファイルは変更しないでください。

- リポジトリ：<owner/repo>
- 作業場所：<worktreeの絶対パス>（ブランチ agent/<N>-<slug>）
- Issue：<タイトル>
<Issue本文をそのまま貼る>

最後のメッセージにプランを書いて止まってください。
```

## 差し戻し（手順5で不可のとき、同じスレッド）

```
プランが差し戻されました。ユーザーの言葉は次のとおりです（原文）：
「<ユーザーの言葉>」
team-plan スキルに従ってプランを書き直し、最後のメッセージに書いて止まってください。
```

## 実装依頼（手順7、同じスレッドを実装用モデルに切り替えてから）

```
プランが承認されました。team-implement スキルに従って実装し、draft PR を出してください。

承認されたプラン（判断点への答えを含む）：
<承認されたプラン本文>
ユーザーの答え（原文）：
「<判断点への答え。なければ「なし」>」

終わったら、PR番号・最新のコミットSHA・ゲートの結果・未確認事項を返してください。
```

## レビュー依頼（手順8、Codex・読むだけ）

```
team-review スキルに従って、PR #<PR>（ブランチ agent/<N>-<slug>、SHA <SHA>）を徹底的にレビューしてください。
ファイルの変更・コミット・push・GitHubへの書き込みはしないでください。

- 作業場所：<worktreeの絶対パス>
- Issue #<N>：<タイトル>（受け入れ条件：<抜き出し>）
- 承認されたプラン：
<承認されたプラン本文>

結果は team-review スキルの書式で返してください。
```

## 修正依頼（手順10、実装した同じスレッド）

```
レビューの指摘について、ユーザーが次のとおり決めました（原文）：
「<ユーザーの答え>」

対象の指摘：
<指摘シートの表のうち、関係する行>

team-implement スキルの「修正」の手順に従い、「直す」になったものだけを直してください。
「見送る」になったものは変更せず、PR本文の「レビュー対応」に理由を書いてください。
終わったら、最新のコミットSHAとゲートの結果を返してください。ready にはまだしないでください。
```

## ready の指示（手順11の確認後）

```
確認が済みました。`gh pr ready <PR>` を実行して、結果を返してください。
```
