# 徹底レビュー（読むだけ）

## 守ること

- **ファイルを変更しない**。コミット・push・PRへのコメントや承認など GitHub への書き込みもしない。結果はこのスレッドの最後のメッセージで返す。
- `AGENTS.md` と `.agents/team/profile.md` を先に読む。
- 指摘ごとに、確かめた事実（file:line、コマンドの結果）と推測を分ける。推測だけの指摘は重大度を1段下げ、「推測」と書く。
- 秘密情報（`.env`、キー、トークン、環境変数の値）を読まない・表示しない。

- 読み方は `.agents/skills/token-budget/SKILL.md` の「読む量を絞る」に従う。ただし差分と、変えた箇所の呼び出し元は省略せずに読む。

## 手順

1. 対象を確かめる：`git branch --show-current`、`git rev-parse HEAD` が依頼のSHAと一致するか。違えばそのことを報告する。
2. 差分を読む：`git fetch origin main`（できなければ省略して書く）、`git diff origin/main...HEAD --stat`、`git diff origin/main...HEAD`。
3. **プランとの一致**：承認されたプランにない変更、プランにあるのにやっていない変更。
4. **正しさ**：Issueの受け入れ条件を満たすか。境界値・空・異常値・エラー時の動き。
5. **回帰**：変えた関数・ファイルの呼び出し元を `git grep` でたどり、挙動が変わる箇所を挙げる。
6. **例外ケース**：`profile.md` の「例外ケースの観点」を1つずつ確かめる。確かめられなかったものは「未確認」に書く。
7. **テスト**：新しい挙動を確かめるテストがあるか。テストが消された・skip された・期待値が実装に合わせて弱められていないか。
8. **でっち上げの検出**：import・呼び出している関数・コマンド・パッケージが実在するか（`git grep`、依存定義ファイル）。
9. **安全**：秘密情報の混入、入力の検証、HTMLへの埋め込み（XSS）、パスの扱い、個人情報の扱い、外部への通信や課金の追加。
10. **ゲート**：実行できる環境なら `.agents/team/gate.sh` を実行する。サンドボックスで実行できなければ実行していないと書き、実装役の報告を引用する（自分の結果として書かない）。

## 返す書式

```
## レビュー：PR #<PR>（SHA <短縮SHA>）
総評：<1〜2行。マージしてよい状態か、何が残っているか>

| ID | 重大度 | 場所 | 指摘（事実／推測） | 提案 |
|----|--------|------|--------------------|------|
| R1 | blocker | path:line | … | … |

重大度：blocker（直さないと壊れる・危ない）／major（直すべき）／minor（直すと良い）／nit（好み）
指摘は重い順、最大10件。nit は3件まで。

確かめたこと：<コマンドと結果の要点>
確かめていないこと：<実機・本番・実行できなかったテストなど>
レビュー担当：<プロバイダー／モデル>
```

承認や「マージしてよい」の決定はしない。決めるのはユーザー。
