# プランだけ書いて止まる

## 守ること

- **ファイルを変更しない**。コミット・push・GitHubへの書き込みもしない。読む・検索する・既存のテストを実行して現状を知ることはしてよい。
- `AGENTS.md` と `.agents/team/profile.md` を先に読む。
- 書く内容は「事実（コードや文書で確かめた）」「仮説」「提案」を区別する。確かめていないファイル・関数・パッケージ・コマンドを前提にしない。必要なら `git ls-files` と `git grep` で確かめてから書く。
- 新しい依存パッケージ、スキーマ・保存形式の変更、`profile.md` の「触る前に承認が要る場所」への変更、有料サービスが必要になる場合は、プランの「決めてほしいこと」に出す。自分で決めない。
- 作業場所が正しいことを最初に確かめる：`git rev-parse --show-toplevel` と `git branch --show-current`（`agent/<Issue番号>-...` のはず）。違えば止まって報告する。

- 読み方は `.agents/skills/token-budget/SKILL.md` の「読む量を絞る」に従う。場所を `git grep` などで特定してから関係する範囲を読む。プランの各項目の根拠に必要なものは必ず読む。

## プランの書式（最後のメッセージにこのまま書く）

```
## プラン：#<Issue番号> <タイトル>

### 目的と受け入れ条件
- <Issueの受け入れ条件を、確かめられる形で>

### 今のしくみ（事実）
- <関係するファイル・関数と、その役割。file:line を添える>

### 変えること
1. <手順。どのファイルの何を、なぜ>
変更するファイル（予定）：<一覧>
触らないもの：<一覧>

### 確かめ方
- ゲート：`.agents/team/gate.sh`
- 追加の確認：<既存のテスト・スクリプト名。新しく書くテストがあれば、何を確かめるか>
- 確かめられないこと：<実機・本番など>

### 危ない点と例外ケース
- <profile.md の「例外ケースの観点」のうち関係するもの、ほかに気づいたもの>

### 規模
小／中／大（理由：<一言>）

### 決めてほしいこと
1. <判断点>：案A <…> ／ 案B <…>（おすすめ：<案>、理由：<一言>）
（なければ「なし」）
```

書いたら止まる。実装は、統括から承認済みのプランが届いてから `team-implement` スキルで行う。
